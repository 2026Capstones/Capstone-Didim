# 프로젝트 규칙 및 지침서 (Harness)

이 파일은 프로젝트 전반에 걸쳐 코드를 작성할 때 반드시 준수해야 하는 규칙과 지침을 정의합니다.

## 1. 코딩 컨벤션
- **언어:** Java 17
- **Gradle:** 9.3.0
- **Spring Boot:** 3.4.1 (Java 17 및 Gradle 9.x 호환 버전)
- **명명 규칙:** 
  - 클래스: PascalCase (예: `UserService`)
  - 변수/메소드: camelCase (예: `getUserInfo`)
  - 상수: UPPER_SNAKE_CASE (예: `MAX_RETRY_COUNT`)
- **주석:** 주요 비즈니스 로직 및 복잡한 알고리즘에는 한글로 설명을 추가합니다.

## 2. 백엔드 (Spring Boot) 계층별 규칙
- **Controller:** 
  - 비즈니스 로직을 포함하지 않고 `Service`를 호출하는 역할만 수행합니다.
  - 응답 형식은 공통 DTO를 사용합니다.
- **Service:**
  - 실제 비즈니스 로직을 처리하며, 트랜잭션(`@Transactional`) 관리를 담당합니다.
- **Domain (Entity):**
  - 데이터베이스 테이블과 매핑되며, Setter 사용을 지양하고 생성자나 Builder 패턴을 사용합니다.
- **DTO:**
  - 계층 간 데이터 전송에만 사용하며, Entity를 직접 외부에 노출하지 않습니다.

## 3. 기록 관리
- 모든 주요 변경 사항은 `docs/fixs.md`에 기록합니다.

## 4. 프로젝트 개발 및 운영 원칙
- **예제 격리:** `/test` 폴더 내의 파일들은 기능을 구현하기 위한 **참고용 예제**일 뿐입니다. 절대로 `/test` 폴더의 코드를 직접 수정하거나 해당 폴더를 실행하지 마십시오.
- **실제 개발 경로:** 모든 실제 프로젝트 개발, 수정 및 빌드는 반드시 **`/src` 폴더** 내에서만 이루어져야 함을 명심하십시오.
- **연동 불가:** `/test` 폴더와 메인 프로젝트(`/src`) 간의 어떠한 직접적인 코드 연동이나 의존성 관계를 생성하지 않습니다.
